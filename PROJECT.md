# BrandBox: аудит, концепция и запуск

## Источники и пределы исследования

Проверено 12 октября 2026 года: [главная «Градиента»](https://gradient-nsk.ru/), [политика](https://gradient-nsk.ru/privacy). Использована доступная текстовая версия живого сайта. Отдельный HTML-код заказчик не приложил: вложение содержит только техническое задание. Мобильный интерфейс, DOM форм, сетевые запросы, реальные отправки и показатели скорости референса не проверены. Страницы двух согласий не удалось получить через инструмент просмотра. Копии фотографий, разметки и фирменных элементов не использованы.

Заявка предлагается через модальное пошаговое оформление. Наблюдаемая форма включает выбор продукции, дополнения, имя, телефон, способ связи, необязательный Telegram и два согласия. Фактическая работоспособность не проверена.

## Позиционирование

Варианты УТП: «Точный оттиск. Понятный заказ.»; «Ваше дело. Ваш оттиск.»; «От задачи до макета — без лишних шагов». Первый выбран как смысловое обещание, второй — как выразительный заголовок. УТП опирается на сценарий, а не на вымышленные сроки или преимущества производства.

## Карта сайта и прототип

`/` — главная: шапка → предложение → каталог → подход → четыре шага → выбор оснастки → индивидуальный макет → FAQ → контакты → подвал.

`/catalog/` — весь ассортимент и фильтры. `/catalog/{slug}/` — семь страниц продукции с описанием, условиями, вариантами, заявкой и связанной продукцией. `/about/`, `/delivery/`, `/contacts/` — информационные страницы. `/privacy/`, `/consent/`, `/marketing-consent/` — обозначенные заготовки документов. Предусмотрена 404.

Категории ИП, ООО, врачей, штампов, факсимиле, аксессуаров и индивидуальных макетов — предложение для согласования, не подтверждение наличия. Услуга восстановления по оттиску не заявляется. Раздел оснасток обозначен как рекомендации по назначению, без вымышленных данных популярности.

Текущий вариант от 15 октября 2026 года использует предоставленный заказчиком логотип: белый куб в оранжевом круге. Исходный файл скопирован без изменений в public/logo.png. Цвет из файла — #EF7F1A. Основной тёмный цвет — #202020, светлый фон — #F6F5F3, карточки белые. Для мелких текстовых ссылок используется тёмный оранжевый #A44700.

Название в интерфейсе — «Брендбокс». Удалены английские надписи, буквенные декоративные метки и повторяющиеся рекламные слоганы. Заголовки и описания сокращены до информации о продукции, выборе и заказе. Технические имена файлов, программные идентификаторы и адреса не переводились.

Использован локальный шрифт с кириллицей и лицензией в public/. Предметные иллюстрации выполнены в фирменных цветах и обозначены как иллюстрации. Рекламные изображения целиком не публиковались: они содержат английские надписи. Исходные файлы CDR не изменялись.

## Функциональная архитектура

Next.js App Router + React + TypeScript + Tailwind CSS, статический экспорт. Каталог хранится в `lib/catalog.ts`; общие интерактивные компоненты — `components/site.tsx`. В формах действует деморежим: данные находятся только в памяти компонента и очищаются при закрытии. Нет фиктивного успешного отправления, CRM, оплаты или загрузки.

Интеграционная граница `lib/order-api.ts`: POST JSON → серверная проверка → сохранение → реальный ID → подтверждение. Перед активацией добавить endpoint, состояние отправки, повтор при ошибке, защиту от повторных запросов, лимиты, серверную валидацию, журнал версии согласия и CRM. Для файлов — отдельная загрузка с проверкой размера, расширения и содержимого, антивирусной обработкой и ограничением доступа. Не подключать произвольный клиентский CRM-секрет.

## SEO и запуск

Уникальные title/description, H1, canonical, sitemap, Open Graph, семантическая разметка. Organization и FAQPage присутствуют на главной, Product — на страницах, без вымышленных offers и рейтингов. LocalBusiness отложен до фактических данных. Черновик закрыт от индексации через robots и metadata; после запуска заменить запрет. SVG OG следует заменить PNG/JPEG для лучшей совместимости социальных сетей. Проверка Lighthouse и реальные Core Web Vitals не заявляются без измерений.

## Локальный запуск

`pnpm install`, `pnpm dev`, затем открыть http://127.0.0.1:3000. `pnpm typecheck` и `pnpm build` проверяют проект. Результат статической сборки — `out/`. Для другого домена обновить `origin` в `lib/catalog.ts`.

Готовый экспорт можно открыть без установки зависимостей: запустить `START.ps1` в PowerShell и перейти по указанному адресу. Требуется Node.js. Закрытие сервера — Ctrl+C.

## Фактическая проверка

Production build Next.js завершён успешно; все статические маршруты и XML/TXT сгенерированы. TypeScript прошёл без ошибок. Для ограниченной Windows-среды добавлена конфигурация Babel вместо SWC; для обычного окружения её можно убрать после проверки сборки. В этой среде для установки использовался npm, создан `package-lock.json`; воспроизводимая установка — `npm ci`.

Визуальная проверка в браузере, реальные клики, проверка консоли и Lighthouse не выполнены: браузерный инструмент получил тайм-аут соединения с локальным сервером. Адаптивные состояния, focus и reduced-motion реализованы в CSS, но требуют визуального QA на целевых ширинах до коммерческого запуска.

Создан приватный объект Sites, однако исходники не синхронизированы и сайт не опубликован: автоматическая проверка разрешений отклонила передачу авторизации через stdin в helper. Зарегистрированный URL не является работающей публикацией. Сохранён локальный проект и готовый экспорт.

## Сервер заявок и подготовка к публикации

Добавлен необязательный серверный режим Next.js без смены интерфейса. API pages/api/orders.ts валидирует вход, проверяет Origin, согласие, honeypot, Turnstile и общий Redis REST лимит. Передаёт заявку только настроенному HTTPS-получателю с серверной авторизацией, HMAC и ключом идемпотентности. Только реальное подтверждение accepted + ID приводит к успеху. Получателя пока нет, деморежим сохранён.

Добавлены pending/error/success состояния формы и повтор защиты после ошибки. Живой интерфейс невозможно собрать без полной конфигурации и согласованных версий документов/origin. Статический экспорт по-прежнему не имеет работающего API.

Production-сборки статического и серверного режима прошли. Выполнены 31 серверная проверка с mock внешних сервисов, 12 HTTP-проверок запущенного Next.js с отключённой доставкой, 14 проверок формы, 9 статических HTTP-проверок. Все 17 HTML-файлов и семь страниц продукции проверены на маршруты, ресурсы, якоря и метаданные. Серверные имена конфигурации не обнаружены в клиентских JS-файлах экспорта. Реальный получатель и браузерные клики не проверялись.

Sites: текущее состояние прочитано штатным инструментом — приватный проект есть, публикации нет. Запрещённая передача авторизации не повторялась. Vercel подготовлен конфигурацией, но не опубликован. Инструкция и необходимые переменные находятся в DEPLOYMENT.md и .env.example.

## Закреплённое меню

Шапка закреплена через position: sticky с top: 0, непрозрачным фоном и слоем выше контента. Полоса деморежима остаётся в потоке и уходит вверх. Отступ прокрутки к якорям учитывает шапку на широком и узком экране. Высота раскрытого мобильного меню ограничена видимой областью, длинное меню можно прокрутить.

## График работы

Добавлен подтверждённый заказчиком график: Пн-Пт: 09:00-17:00; Сб-Вс: выходной. Значения заданы в lib/contacts.ts и используются в контактной панели главной страницы и страницы контактов, а также под адресом в подвале. На широком экране график занимает третью колонку рядом с телефоном и почтой, на узких экранах следует отдельным блоком.

## Получение и оплата

Пустой текстовый блок заменён тремя компактными карточками: сроки, получение, оплата. Срок, место и способ получения, доставка, окончательная стоимость и порядок оплаты описаны как согласуемые условия. Конкретные неподтверждённые сроки, способы оплаты и доставка не обещаются. На узком экране карточки идут одной колонкой.
